# План развития приложения ai-message (app.77ais.ru)

> Дорожная карта развития **продукта** (SPA `apps/web` + backend `apps/api` +
> worker + NLP) с учётом того, что мы уже работаем в Kubernetes.
> Дополняет [`docs/PLAN.md`](./PLAN.md) (история фаз 0–7) и не дублирует его:
> здесь — что делать **дальше**. Лендинг описан в [`SITE_PLAN.md`](./SITE_PLAN.md),
> коннекторы — в [`PLAN_CONNECTORS.md`](./PLAN_CONNECTORS.md).
>
> Документ — «меню» направлений. Не всё делается сразу и не всё подряд:
> в конце есть приоритизация (P0→P3) и предлагаемые срезы-релизы.

## 1. Где мы сейчас (краткий срез)

**Готово и в проде (k8s, Cloud.ru):**
- Аутентификация + multi-tenancy (один user = один tenant), JWT + refresh-cookie.
- Подключение Bitrix24 «в один клик» (тиражное приложение, OAuth, поллер + webhook).
- Импорт диалогов Открытых линий, CRM-привязка (сделки/лиды), кэш операторов.
- Дашборд: 8 KPI с дельтами, таймлайн, donut по каналам, менеджеры, heatmap,
  SLA-нарушения, топ-контакты, воронка.
- Inbox: список диалогов, фильтры, поиск, sentiment-бэйджи, чипы тем, сущности
  (NER), сводка диалога (LLM), похожие диалоги (pgvector).
- NLP: sentiment, теги (41 тема), резюме, entities, эмбеддинги — всё в worker
  под distributed-локами, авто-cron.
- Инфра: ingress-nginx + cert-manager (TLS), образы в реестре, Kaniko-сборка.

**Заложено, но не закрыто:**
- AI-таб — частью на реальных данных (sentiment/tags), частью заглушки.
- BERTopic (6.4), Weekly insights + аномалии + AI Control Panel (6.7).
- Email-верификация, инвайты в команду, роли кроме admin/member.
- Observability (метрики/логи/Sentry), бэкапы, HPA, CI/CD в k8s.
- Другие каналы (email, Telegram, WhatsApp), другие CRM (amoCRM/HubSpot).
- Биллинг и тарифы (лендинг уже обещает Старт/Pro/Enterprise).

**Слабые места UX (выявлено при ревью кода):**
- Нет мобильной адаптации (sidebar фиксированный `w-60`).
- Нет глобального поиска / командной палитры (Cmd+K).
- Нет уведомлений и центра алертов (SLA-нарушения видны только на дашборде).
- Settings — минимальный экран (98 строк): нет профиля, команды, биллинга, API-ключей.
- Нет отдельной страницы просмотра диалога (всё в карточках Inbox).
- Нет тёмной темы (в Tailwind `darkMode: class` объявлен, но не используется).
- Нет онбординга после регистрации (пустой дашборд без проводника).

## 2. Треки развития

Восемь параллельных треков. Внутри каждого — варианты от «быстрых побед»
до крупных эпиков. Метки усилий: 🟢 малое (≤2 дня), 🟡 среднее (до недели),
🔴 крупное (недели/эпик).

---

### Трек A — Продуктовые фичи (ядро ценности)

A1. 🟢 **Страница просмотра диалога** (`/inbox/:id`) — полноэкранная переписка
    с пузырями, per-message раскраской sentiment, таймлайном, панелью CRM-сделки
    сбоку. Сейчас всё ютится в карточке списка.
A2. 🟡 **Глобальный поиск** по всем сообщениям/контактам/сделкам (FTS уже есть,
    нужен единый endpoint + UI с группировкой результатов и подсветкой).
A3. 🟡 **Saved views / сегменты** — сохранённые фильтры Inbox («негатив за неделю
    по WhatsApp без ответа») с быстрым доступом из сайдбара.
A4. 🟡 **Центр уведомлений и алертов** — SLA-нарушение, всплеск негатива, новый
    диалог без ответа > N минут → колокольчик в шапке + опционально email/Telegram.
A5. 🟡 **Экспорт и отчёты** — CSV/XLSX выгрузка диалогов и метрик, планировщик
    «еженедельный отчёт на почту» (PDF/HTML).
A6. 🔴 **Обогащение CRM из чата** — автозапись найденных телефонов/email/сумм
    (entities) в карточку сделки/контакта Bitrix24 (запись назад в B24 REST).
A7. 🔴 **Карточка контакта 360°** — агрегат всех диалогов, каналов, сделок,
    тональности и сущностей по одному клиенту (cross-channel identity).
A8. 🟡 **Командные комментарии / заметки** к диалогу (внутренние, не уходят клиенту).
A9. 🟢 **Bulk-действия в Inbox** — массовое тегирование, отметка «прочитано»,
    запуск анализа по выборке.

---

### Трек B — AI / NLP (достройка фазы 6 + новое)

B1. 🟡 **AI Control Panel (6.7)** — единая страница статуса всех NLP-фич:
    доля проанализированного, последний прогон cron, ручные триггеры,
    стоимость токенов. Заменяет разрозненные кнопки.
B2. 🔴 **Weekly insights (6.7)** — smart-LLM раз в неделю собирает дайджест:
    что выросло/упало, топ-темы, проблемные диалоги → отчёт в кабинете + email.
B3. 🟡 **Детекторы аномалий (6.7)** — всплески объёма, скачки SLA, пики негатива;
    статистические пороги (z-score/MAD) + уведомления (см. A4).
B4. 🔴 **BERTopic (6.4)** — динамические темы поверх готовых эмбеддингов вместо
    статичного словаря из 41 темы; ежесуточный пересчёт `topic_clusters`.
B5. 🟡 **Семантический поиск для пользователя** — «найди диалоги про возврат
    денег» через эмбеддинг запроса (инфраструктура pgvector уже есть).
B6. 🟡 **Quality score диалога** — LLM-оценка качества ответа оператора
    (вежливость, решена ли проблема, скорость) → рейтинг менеджеров.
B7. 🔴 **Churn-risk / следующий-best-action** — предсказание оттока по
    тональности + истории, подсказка оператору.
B8. 🟢 **Превратить AI-таб заглушки в реальные карточки** — sentiment/tags уже
    есть, подключить остальные по мере готовности B-фич, убрать «скоро».
B9. 🟡 **Контроль расходов на LLM** — учёт токенов/стоимости per-tenant,
    лимиты, выбор модели в Settings (fast/smart).
B10. 🔴 **RAG-ассистент по базе диалогов** — чат «спроси свою переписку»
    (эмбеддинги + smart-LLM), отвечает со ссылками на источники.

### Трек D — Инфраструктура Kubernetes

D1. ✅ **CPU-only torch** — `torch` привязан к индексу `download.pytorch.org/whl/cpu`
    через `[tool.uv.sources]` в `apps/api/pyproject.toml`. Резолвится `torch==…+cpu`,
    nvidia-* CUDA-пакеты ушли (0 шт.) → образ api ужимается кратно. CI ставит
    CPU-torch отдельным шагом (plain pip не читает `[tool.uv.sources]`).
D2. ✅ **CI/CD в k8s** — `deploy.yml`: на push в `main` buildx собирает api+web на
    GitHub-runner (после D1 образ влезает), пушит `:<sha>`+`:latest` в реестр,
    затем `kubectl set image` + `rollout status` (push-модель, без Argo). Секреты
    `REGISTRY_USERNAME/PASSWORD` + `KUBECONFIG_B64`, см. `infra/k8s/README.md §5`.
D3. 🟡 **Бэкапы Postgres** — CronJob `pg_dump` → S3 Cloud.ru (помним правило:
    [[s3-backup-local-first]] — сначала локально, потом в S3), retention + проверка
    восстановления.
D4. 🟡 **Метрики** — `prometheus-fastapi-instrumentator` в api, kube-prometheus-stack
    (Prometheus+Grafana), дашборды по latency/ошибкам/очереди arq.
D5. 🟡 **Логи** — Loki + Grafana (или агрегатор Cloud.ru), структурные JSON-логи.
D6. 🟢 **Sentry** FE + BE — ловить JS-ошибки лендинга/SPA и исключения api.
D7. 🟡 **Автоскейл** — HPA для api/worker по CPU/длине очереди; PodDisruptionBudget.
D8. 🟢 **Надёжность подов** — readiness/liveness аудит, resource requests/limits,
    `topologySpreadConstraints` (когда станет >1 ноды).
D9. 🟡 **Postgres production** — оценить managed-Postgres Cloud.ru vs in-cluster;
    PITR, реплика для чтения аналитики.
D10. 🟡 **Секреты** — внешний секрет-менеджер (Sealed Secrets / External Secrets),
    ротация `ENCRYPTION_KEY` (MultiFernet уже поддерживает `new,old`).
D11. 🟢 **NetworkPolicy** — ограничить трафик между подами (Cilium уже CNI).
D12. 🟡 **Staging-неймспейс** — отдельный контур для проверки релизов до прода.
D13. 🟢 **Зафиксировать build-манифесты** (ctx-loader + kaniko Job + PVC) в
    `infra/k8s/build/` для воспроизводимости сборки.
